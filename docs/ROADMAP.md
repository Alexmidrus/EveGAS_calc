## Этап 1. Ядро расчёта — самый важный этап

Здесь 60% ценности проекта. Не торопись и не переходи дальше, пока не пройдёт
контрольный пример из `docs/DOMAIN.md` §5.

- [x] `app/core/constants.py` — коэффициенты разжатия, список хабов, сбор за обеспечение
- [x] `app/core/catalog.py` — загрузка `data/gases.json`, поиск газа по ключу
- [x] `app/core/models.py` — dataclasses:
  - `CalcInput` — газ, N, структура, GDE, брокер, режим и сумма обеспечения, флаг включения в итог
  - `HubPrices` — ставка доставки и четыре цены (любая может быть `None`)
  - `Scenario` — одна строка результата со всеми промежуточными числами
  - `CalcResult` — список сценариев, сводка, точки безубыточности, предупреждения
- [x] `app/core/calculator.py` — чистые функции:
  - `decompression_efficiency(structure, gde_level) -> float`
  - `required_compressed_qty(n, eta) -> int`
  - `build_scenarios(inp, prices_by_hub) -> CalcResult`
  - `breakeven_compressed_price(eta, p_raw, volume, rate) -> float`
- [x] `tests/test_calculator.py`:
  - контрольный пример целиком, все десять строк с точностью до сотых
  - граничные значения eta: 0.80 и 0.95
  - `ceil` и `floor` на некруглых числах
  - пропуск сценариев с незаполненными ценами
  - оба режима обеспечения
  - хаб без ставки доставки полностью выпадает

Напоминание: `calculator.py` не импортирует Flask. Вообще ничего, кроме stdlib и `models.py`.

## Этап 3. Подтяжка цен из ESI

- [x] `app/services/cache.py` — dict с TTL
- [x] `app/services/orderbook.py` — фильтрация, отсечение выбросов, VWAP
- [x] `tests/test_orderbook.py` на фикстурах, без сети
- [x] `app/services/esi.py` — async-клиент, заголовки, ретраи, пагинация
- [x] `POST /fetch-prices` — запросы через `asyncio.gather`
- [x] Подтянутые цены визуально отличаются от введённых руками и перебиваются
- [x] Предупреждения о глубине стакана в таблице результата
- [x] Сноска об ограничениях: buy-ордера с числовым радиусом и рынки игровых структур

Все правила разбора — в `docs/ESI.md`, особенно §3.2 про радиус buy-ордеров.
Это место, где ошибка не видна глазом.

Решения, принятые по ходу этапа:

- **Запросов пока 5, а не 10.** `raw_type_id` во всём `data/gases.json` — `null`,
  выдумывать ID нельзя. Подтягиваются только колонки сжатого газа, а под сеткой
  прямым текстом написано, почему сырые колонки пустые. Станет 10 автоматически,
  как только `tools/build_gases.py` (этап 4) заполнит `raw_type_id`.
- **`X-Compatibility-Date` сдвинута на 2026-08-13.** ESI сравнивает дату со своим
  днём по UTC-11 и на «сегодня» отвечает 400. Подробности — `docs/ESI.md` §2.
- **`system_id` хабов.** Нужен для отбора buy-ордеров, но в `DOMAIN.md` его нет.
  В справочнике он заполнен только у Jita (задокументирован в `ESI.md` §2),
  у остальных — `null`, и `orderbook.py` определяет его из самого стакана
  по ордеру на станции хаба.
- **Глубина стакана** ездит между сеткой и расчётом скрытым полем и сравнивается
  с потребностью в `calculator.py`. Ручная правка цены стирает глубину: она
  относилась к той цене, которой больше нет.

## Отложено

Не делать без отдельной просьбы:

- Дизайн и оформление — будет отдельной задачей после того, как логика заработает
- Раздельный расчёт для нескольких газов сразу
- Split-sourcing: набрать часть партии в одном хабе, часть в другом
- История цен, графики, база данных
- Рынки игровых структур (требует SSO)
- Именованные пресеты настроек (потребует SQLite)
- Учёт числа курьерских контрактов при лимите объёма на контракт
