# CLAUDE.md — правила работы над проектом GasLens

## Что это

**GasLens by EveCraft** — веб-калькулятор для EVE Online. Отвечает на один вопрос: **где сегодня выгоднее купить
конкретный газ для производства** — с учётом того, что газ торгуется в сжатом и несжатом
виде, что разжатие теряет часть объёма, и что доставка из разных хабов стоит по-разному.

Результат — одна таблица, отсортированная по итоговой цене за один *полезный* юнит
сырого газа, доставленного к производственной точке.

## Жёсткие ограничения

Их нельзя нарушать без явного согласования с пользователем:

- **Никакого Docker.** Проект должен запускаться на любом хостинге с Python: `pip install -r requirements.txt && python run.py`.
- **Никакого Node.js, npm, сборщиков, TypeScript.** Фронт — Jinja2-шаблоны + HTMX + минимум ванильного JS.
- **Максимум 9 зависимостей** в `requirements.txt`: `Flask`, `httpx`, `asgiref`, `waitress`, `SQLAlchemy`, `alembic`, `psycopg[binary]`, `PyMySQL`, `PyJWT[crypto]`. Добавление десятой — только с обоснованием.
- **Flask, не FastAPI.** Async-режим через `flask[async]` используется только для параллельных запросов к ESI.
- **SDE не является зависимостью приложения.** Справочник газов лежит в репозитории готовым файлом `data/gases.json`. Скрипт-генератор в `tools/` запускается разработчиком вручную и в рантайме не участвует.
- **База данных — с версии 0.1.0.** SQLite в dev-профиле, MariaDB / MySQL / Postgres в prod. Один код на все четыре через SQLAlchemy, схема — только через миграции Alembic. До 0.1.0 приложение было stateless; в истории коммитов это не ошибка.
- **ESI опрашивает только сборщики по расписанию.** Пользователь не инициирует обращений к ESI ни при каких условиях: 200 человек с кнопкой «подтянуть цены» — это бан. Сбор запускается системным cron: `python -m app.jobs.collect` каждые 30 минут за стаканом и `python -m app.jobs.collect_history` раз в сутки за историей сделок. Приложение читает из базы.
- **Авторизация — только EVE SSO и только ради настроек.** Пустой список scope, никаких приватных данных персонажа. Анонимный доступ обязан работать всегда: без логина настройки живут в `localStorage`, расчёт доступен полностью.

## Стек

```
Python 3.11+
Flask 3 (+ flask[async])
httpx (async client)
SQLAlchemy 2 + Alembic (SQLite в dev, MariaDB / MySQL / Postgres в prod)
PyJWT[crypto] (проверка токена EVE SSO)
Jinja2 + HTMX + ванильный JS
waitress (прод-сервер)
pytest (тесты)
```

## Порядок работы

**Всегда начинай с `docs/ROADMAP.md`.** Этапы идут строго по порядку, каждый заканчивается
работающим и протестированным куском. Не забегай вперёд: не пиши ESI-клиент, пока не готов
и не покрыт тестами калькулятор.

Перед тем как писать математику — прочитай `docs/DOMAIN.md`. Все константы, формулы и
коэффициенты там. Не выводи их заново из головы.

## Правила кода

- **`app/core/calculator.py` не импортирует ничего, кроме stdlib и `app/core/models.py`.** Ни Flask, ни httpx, ни Jinja. Это переиспользуемое ядро, оно должно работать в обычном скрипте.
- Имена переменных, функций, файлов — **на английском**. Докстринги и комментарии — **на русском**. Тексты интерфейса — на русском.
- Деньги считаем в `float`, но **любое число, попадающее в шаблон, округляется явно** через хелпер форматирования. Никаких `2751.0000000004` на экране.
- Все игровые константы — только в `app/core/constants.py` или в `data/gases.json`. Магических чисел в бизнес-логике быть не должно.
- Типизация обязательна: аннотации на всех публичных функциях, dataclasses для структур данных.
- Тесты пишутся вместе с кодом, а не после. Для калькулятора — с числовыми примерами из `docs/DOMAIN.md`.

## Чего делать нельзя

- **Не выдумывать type_id, station_id и region_id.** Всё, что известно, лежит в `data/gases.json` и `docs/DOMAIN.md`. Если ID неизвестен — поле остаётся `null`, и это должно быть видно, а не заполнено правдоподобной чушью.
- **Не расширять то, что даёт вход.** EVE SSO есть с версии 0.1.0, но только ради
  хранения настроек: пустой список scope, из токена берутся идентификатор и имя,
  refresh-токен не сохраняется. Анонимный режим — основной и полный, и таким обязан
  остаться: расчёт без входа доступен целиком, настройки живут в `localStorage`.
- **Оформление — по `docs/SPEC.md` §10 и по макету «GasLens Terminal» в каталоге `EveGAS_calc дизайн/`** (с версии 0.3.0, этап 12). Прежнее правило «минимальное оформление, системный шрифт, никаких иконок и анимаций» отменено. Что осталось в силе: никакого CSS-фреймворка, npm и сборщиков — один `app/static/style.css`, написанный руками; никаких внешних запросов в рантайме — шрифты лежат своими файлами в `app/static/fonts/`, страница обязана открываться без интернета. Макет — источник вёрстки и палитры, но не источник чисел и не источник кода: математика остаётся в `app/core/calculator.py`, значения — в `docs/DOMAIN.md`.
- **Не давать пользователю дотянуться до ESI.** С версии 0.1.0 в ESI ходит только
  сборщик по расписанию (`python -m app.jobs.collect`), приложение читает из базы.
  Кнопка «подтянуть цены» в руках у двухсот человек — это бан от CCP. Кэшировать
  агрессивнее самого ESI (5 минут) тоже нельзя.
- Не молчать об ошибках. Если ESI не ответил по одному из хабов — показать это в интерфейсе, а не подставить ноль.

## Что важнее всего

Приложение считает деньги. Ошибка в формуле или в разборе стакана дороже, чем кривая
вёрстка. Если сомневаешься между «красиво» и «проверяемо» — выбирай проверяемо и добавь тест.
